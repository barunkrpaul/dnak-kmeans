# DNAK: Delaunay-Neighbor Accelerated k-means

Exact acceleration of Lloyd's k-means algorithm using the Delaunay graph of
the current centroids. DNAK produces exactly the same clustering as Lloyd's
algorithm (same iterations, same assignments, same centroids) while
computing far fewer point-to-centroid distances.

This repository accompanies the manuscript

> B. Kr. Paul and K. Giri, *DNAK: Exact Acceleration of Lloyd's k-Means
> via Delaunay-Neighbor Pruning*.

Every table and figure in the paper is generated by the scripts in
`experiments/` from the raw per-run files in `results/`.

## How DNAK works

For every point DNAK stores its assignment, an upper bound and a lower
bound, the same O(n) state as Hamerly's algorithm. When the bounds cannot
certify the current assignment, the point is not compared with all k
centroids. Instead:

1. a greedy walk on the Delaunay graph of the centroids, started at the
   current centroid, moves to strictly closer neighbours and stops at the
   exact nearest centroid (Lemma 1 of the paper);
2. the second-nearest centroid is always a Delaunay neighbour of the
   nearest one (order-2 Voronoi property, Lemma 2), so the walk also
   returns the exact second-nearest distance, which becomes the new lower
   bound.

## Results in brief

DNAK is exact (proved, including ties, and checked on more than 1,000 runs).
The current method (`DNAK-6` in the code; `DNAK` in the paper) uses
Delaunay-local bounds: a point's lower bound is reduced by the movement of
its centroid's Delaunay neighbours only, new neighbours are bounded through
their edge length, the triangulation is reused under an exact local
Delaunay certificate, and the initial assignment is done by walks. `DNAK`
in the code is the basic version (`DNAK-B` in the paper) with global drift
bounds.

Comparison with the original C++ implementations (eakmeans for Exponion,
the authors' Ball k-means), same centroids, identical output checked, one
Colab session, 3 seeds x 2 repeats (`results/raw_dnak6_original_colab.csv`):

| Configuration | DNAK | Exponion (orig.) | Ball k-means (orig.) | DNAK faster (Exp./Ball) |
|:--|--:|--:|--:|--:|
| Synthetic d=2, k=128 | 0.33 | **0.30** | 0.38 | 0/6, 5/6 |
| Synthetic d=2, k=512 | **0.41** | 0.78 | 0.66 | 6/6, 6/6 |
| Synthetic d=2, k=1024 | **0.41** | 1.81 | 1.14 | 6/6, 6/6 |
| Synthetic d=3, k=512 | 0.95 | 0.85 | **0.57** | 0/6, 0/6 |
| Synthetic d=3, k=1024 | 1.44 | 1.81 | **1.22** | 6/6, 0/6 |
| Uber NYC, d=2, k=256 | **0.43** | 0.69 | 0.67 | 6/6, 6/6 |
| 3D Road Network, k=64 | **1.85** | 2.21 | 5.87 | 6/6, 6/6 |
| Uber NYC, n=1.5M, k=1024 (1 seed) | **2.2** | 12.0 | out of memory | |

Scripts: `experiments/external/build_external.sh` builds the original code,
`experiments/run_dnak6_vs_original.py` runs the comparison,
`experiments/run_paired_b6.py` pairs DNAK with DNAK-B. `DNAK-2` to `DNAK-5`
are intermediate variants kept for the ablation of the ideas; all are exact.

## Installation and quick start

```bash
git clone https://github.com/barunkrpaul/dnak-kmeans.git
cd dnak-kmeans
pip install -e .
```

```python
from dnak_kmeans import dnak, lloyd, make_blobs, kmeanspp_init, is_exact

X = make_blobs(20000, 2, 64, seed=0)
C0 = kmeanspp_init(X, 64, seed=1)
r_dnak = dnak(X, C0)
r_lloyd = lloyd(X, C0)
print(is_exact(r_dnak, r_lloyd))            # True
print(r_lloyd["comps"] / r_dnak["comps"])   # reduction in distance computations
```

The first call compiles the Numba kernels and takes a few seconds; the
compiled code is cached afterwards.

## Reproducing the paper

```bash
cd experiments
./run_all.sh
```

This checks exactness, runs the main benchmark and the k-sweep, and
regenerates every table and figure. The real data sets are downloaded
automatically into `data/` on first use:

* Uber pick-ups, New York City, April 2014, from the public
  [plotly/datasets](https://github.com/plotly/datasets) repository;
* UCI 3D Road Network, North Jutland (Kaul, 2013, doi:10.24432/C5GP51).
  The UCI server blocks scripted downloads, so the identical file is
  fetched from a public GitHub mirror and checked against its MD5 checksum;
* the `china.jpg` and `flower.jpg` sample images shipped with scikit-learn.

The harness writes one row per run and skips finished (configuration,
seed) pairs, so an interrupted run can simply be restarted. On one core
the full benchmark takes roughly two hours. Absolute times depend on the
machine; the paper's numbers were obtained on one core of an Intel Xeon at
2.10 GHz (`results/machine.json`).
